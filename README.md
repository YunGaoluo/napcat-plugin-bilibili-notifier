# napcat-plugin-bilibili-notifier

NapCat B站开播、动态推送插件，监控主播直播与动态信息，推送至QQ群和私聊。

## 功能特性

- **实时监控**：每10秒检查一次主播直播状态，及时推送开播/下播通知
- **动态推送**：每一分钟检查一次主播动态，及时推送动态信息
- **动态卡片**：动态渲染为 B 站风格图片，文字、配图与互动数随消息一起发送，渲染失败自动回退文本
- **群订阅**：支持群聊订阅主播，开播时自动发送到群内
- **私聊订阅**：支持用户私聊订阅，开播时私聊推送
- **@全体功能**：群订阅可开启开播@全体提醒
- **状态显示**：订阅列表显示主播当前直播状态和直播时长
- **权限管理**：群订阅仅管理员可操作

## 快速开始

### 安装

1. 下载 Release 中的 `napcat-plugin-bilibili-notifier.zip`
2. 解压到 NapCat 的 `plugins` 目录
3. 重启 NapCat 或在 WebUI 中启用插件

### 从源码构建

需要 Node.js 20.19+，使用 `package.json` 固定的 pnpm 10.28.2；请勿混用 npm 锁文件。

```bash
pnpm install --frozen-lockfile
pnpm run typecheck
pnpm test
pnpm run build
```

构建产物为 `dist/index.mjs` 和 `dist/package.json`。普通构建不会连接远程调试服务。

## 使用说明

### 命令列表

默认前缀为 `#blive`，可在 NapCat 配置面板修改。下文命令均以默认前缀为例：

| 命令 | 说明 | 使用场景 |
|-----|------|---------|
| `#blive help` | 显示帮助信息 | 任意 |
| `#blive 订阅 <UID>` | 订阅指定主播 | 群聊/私聊 |
| `#blive 删除 <UID>` | 取消订阅主播 | 群聊/私聊 |
| `#blive 列表` | 查看当前订阅列表 | 群聊/私聊 |
| `#blive atall on/off` | 开启/关闭开播@全体 | 仅群聊 |

### 使用示例

**订阅主播：**
```
#blive 订阅 123456
```

**查看订阅列表：**
```
#blive 列表
```

列表会显示：
- 主播昵称和UID
- 当前直播状态（未开播/直播中/轮播中）
- 直播时长（如果正在直播）
- 直播间链接

**开启@全体：**
```
#blive atall on
```

### 配置与权限

- `enabled`：关闭后停止命令处理、B站轮询和消息推送；重新开启后恢复。
- `commandPrefix`：命令解析及帮助提示使用同一配置；空白值回退为 `#blive`。
- `debug`：控制插件详细日志，不记录未命中命令的聊天内容。
- `superusers`：超级管理员 QQ，支持英文或中文逗号分隔。
- `groupConfigs.<群号>.enabled`：设为 `false` 后暂停该群命令和推送；不影响其他群或私聊。
- `renderDynamicCard`：动态是否渲染为图片卡片，默认开启；Gotenberg 不可用或超时会回退为纯文本推送。
- `gotenbergUrl`：Gotenberg 服务地址，默认 `http://Gotenberg:3000`。插件与 Gotenberg 在同一 Docker 网络时使用容器名即可。
- `cardWidth`：卡片宽度，默认 640，限制在 320–1000 之间；图片按 2 倍像素密度输出，高度随内容自适应。

群订阅、取消订阅、@全体设置仅群主、管理员或超级管理员可操作，权限检查在网络请求之前完成。@全体仅用于开播通知，动态和下播通知均不使用。


## 数据存储

插件使用 JSON 文件存储数据，位于插件数据目录：

| 文件 | 说明 |
|-----|------|
| `streamers.json` | 主播基本信息和直播状态 |
| `dynamic_cache.json` | 已处理的动态 ID |
| `group_subs.json` | 群订阅配置 |
| `user_subs.json` | 用户订阅配置 |
| `live_cache.json` | 直播状态缓存 |
| `notification_queue.json` | 未送达事件及其剩余群／私聊目标 |

### 推送可靠性与升级

- 直播与动态各自只运行一轮检查；B站单次请求超时为 10 秒。卸载会取消请求并等待在途检查及发送结束。
- 动态按 ID 去重，同时记录已知动态的最大发布时间；翻页遇到整页早于该边界的条目即停止，这些历史条目只写入缓存不推送。避免新动态触发旧分页导致一次刷出大量历史动态。
- 单轮检查只推送严格晚于该边界的动态，按发布时间由旧到新发送；每条动态渲染约一秒，因此多条更新会依次到达。
- 只推送转发、视频、图文、文字、专栏、音频六类动态；未知类型只记录不推送。单条动态解析失败会跳过该条，不中断整轮检查。
- 直播状态只在字段实际变化时写入 `streamers.json`；直播间批量查询按每 50 个 UID 分块。
- 新订阅首次检查只建立动态基线，包括空动态列表。旧版仅含时间戳的动态缓存升级后会重新建立一次基线，不补发历史内容。
- 待发送事件先持久化，最多保留 24 小时、200 条；超期或超量的旧事件会被丢弃。发送失败只保留失败目标，按 1s、2s、4s… 最长 60s 退避重试；成功目标不会因其他目标失败而再次发送。暂停的群保留待发送记录，取消订阅的目标会被移除。
- 连续发送之间保留 250ms 间隔，降低触发 QQ 风控的概率。
- 订阅限制：单个群或用户最多 50 个主播，全局最多 500 个有订阅的主播；同一会话的订阅命令最小间隔 3 秒。列表按 3000 字符分片发送。
- 主播已开播时新增订阅，会在下一次轮询前补发一次开播通知；该主播最后一名订阅者取消后，直播状态缓存删除，重新订阅按新的开播状态处理。
- 发送采用至少一次语义：若进程在 QQ 已收到消息、但本地送达记录尚未写入时异常退出，重启后仍可能重复发送。
- JSON 使用同目录临时文件替换，写入失败会返回操作失败，不报告订阅成功。
- 旧配置中的前缀会开始实际生效。如果旧配置保存了模板默认值 `#cmd`，希望继续使用旧命令时请将其改为 `#blive`。

## 通知内容

### 开播通知

```
【开播提醒】
{主播名} 开播啦！
标题：{直播间标题}
分区: {父分区} - {子分区}
https://live.bilibili.com/{房间号}
[封面图]
```

### 下播通知

```
【下播提醒】
{主播名}下播了
本次直播时长: {时长}
```

### 动态通知

一条消息内先发标题行，再发渲染后的卡片图片：

```
{主播名} 发布了新{类型}动态！
[动态卡片图片]
```

卡片包含头像、昵称、相对时间、正文、配图网格、视频卡与转发内容，底部为转发/评论/点赞数。不附加链接。渲染失败或超过 4 MB 时，回退为原有的文本推送。

## 注意事项

1. **权限要求**：群订阅/取消订阅需要群主、管理员或配置的超级管理员权限
2. **UID获取**：在B站用户空间页面的URL中可以找到UID
3. **私聊订阅**：私聊订阅仅对该用户生效
4. **群订阅**：群订阅对该群所有成员可见，开播时发送到群内

## 开发

```bash
# 本地构建监听，不部署
pnpm run watch

# 构建并部署、热重载
pnpm run push
# 等价命令
pnpm run deploy

# 监听构建，每次成功后部署并热重载
pnpm run dev
```

远程调试服务地址通过环境变量配置，默认 `ws://127.0.0.1:8998`。在项目根目录创建被忽略的 `.env.deploy`：

```bash
NAPCAT_DEBUG_WS=ws://your-host:8998
# 调试服务启用鉴权时再设置
NAPCAT_DEBUG_TOKEN=your-token
```

远端需要启用 `napcat-plugin-debug`。只有 `deploy` 构建模式启用远程部署；CI 使用普通本地构建。不要把真实地址或 token 提交到仓库。

项目没有独立 WebUI 前端，仅通过 NapCat 原生配置 Schema 展示配置。类型检查先生成已忽略的 `.napcat-types/` 声明镜像，以修正上游将声明发布为 `.ts` 的打包问题；`patches/` 中的 pnpm 补丁修正损坏的返回类型声明。业务代码继续执行严格类型检查，安装时必须保留 `pnpm-workspace.yaml` 和补丁文件。
